# employee-handbook-mipt2026-hack

Кейс № 4: «Навигатор сотрудника по внутренним регламентам».

Система должна находить ответ на вопрос сотрудника в предоставленных документах, формировать порядок действий и подтверждать ключевые выводы источниками.

## Документация

- [TASK.md](materials/TASK.md) — описание задачи, ожидаемый результат, ограничения и требования к сдаче.
- [DOCUMENTS.md](materials/DOCUMENTS.md) — перечень 20 исходных материалов с описаниями.
- [CRITERIA.md](materials/CRITERIA.md) — полная разбалловка, план тестирования и шаблон протокола проверки.
- [AGENTS.md](AGENTS.md) — инструкции для агентов, работающих над проектом.
- [data/README.md](data/README.md) — размещение исходных материалов и границы технической проверки.
- [DATA_PUBLICATION.md](materials/DATA_PUBLICATION.md) — результаты первичной проверки возможности публикации данных.
- [BACKEND_PLAN.md](materials/BACKEND_PLAN.md) — исследование и предлагаемый план бэкенда; пока не реализация.
- [ARCHITECTURE.md](materials/ARCHITECTURE.md) — схема бэкенда диаграммами: контекст, компоненты, ingest, поток ответа, модель данных, развёртывание.

- [materials/VALIDATION.md](materials/VALIDATION.md) — фактически выполненные проверки и состояние VPS/API модели.

## Текущий статус

Сохранены условия кейса и правила разработки. Локально загружены все 20 исходных файлов в `data/raw/`, реестр загрузки — `data/manifest.json`. Эти данные исключены из Git до подтверждения разрешения на публикацию и не входят в клонируемый репозиторий.

Выполнен первичный скрининг данных; разрешение на перепубликацию не подтверждено.

Реализован первый этап бэкенда: локальное чтение PDF/DOCX/XLSX, OCR, E5 embeddings, PostgreSQL + pgvector, атомарные поколения индекса и поиск фрагментов (dense + русский FTS + RRF). Инструкция запуска, проверки и ограничения — в [INGEST.md](materials/INGEST.md). Добавлены HTTP API, страница с открытием цитат по строкам и генерация через внешний Qwen 27B. Автоматическое разрешение редакций и сопровождение состояния процедуры пока не реализованы. Запуск и ограничения — в [DEPLOY.md](materials/DEPLOY.md).

Поиск поддерживает длинные и составные вопросы, соседний контекст, проверяемые цитаты со строками и повторную индексацию без OCR. Проверочный набор, метрики и контракт открытия источника — в [RETRIEVAL.md](materials/RETRIEVAL.md).


## Структура репозитория

Организация следует привычному разделению School 21:

```text
src/navigator/       код бэкенда, API и встроенная страница
  ingest/            извлечение, OCR, embeddings и хранение
  static/            интерфейс демонстрации
tests/               автоматические проверки
materials/           задание, критерии, архитектура и инструкции
code-samples/        генератор синтетических учебных документов
misc/scripts/        служебные проверки развёрнутого сервиса
data/                оригиналы и результаты обработки (локально)
models/              скачанные веса E5 (локально)
secrets/             ключ внешней модели (локально)
```

`pyproject.toml`, `uv.lock`, `Dockerfile`, `compose.yaml` и пример окружения находятся в корне. Команды из инструкций выполняются из корня репозитория. Назначение и статус исходных данных описаны в [data/README.md](data/README.md).
