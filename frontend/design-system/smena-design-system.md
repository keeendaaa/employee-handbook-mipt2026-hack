## Слои системы

1. **Primitives** — исходные цвета. Не использовать напрямую в интерфейсных компонентах.
2. **Semantic** — смысловые роли: surface, text, secondary, accent, warning, highlight и т. д.; spacing и radius сохраняют существующие ID флоу.
3. **Layout** — размеры sidebar/header/content, breakpoints и размеры контролов.
4. **Components** — aliases ролей кнопки, поля и графа. Ссылаются на Semantic.
5. **Text styles** — общие Inter стили; те же значения экспортируются в CSS custom properties.
6. **UI kit** — main components с вариантами и свойствами; **Patterns** — блоки, собранные из экземпляров контролов. **Screens** — контент и компоновка из этой библиотеки.

Четыре коллекции экспортированы в `smena-token-source.json`. `smena-design-tokens.css` и `smena-design-tokens.json` генерируются из этого экспорта командой `python3 work/build-design-tokens.py`. В JSON сохранены реальные Figma IDs и CSS имена. Цветовые aliases не разворачиваются в повторяющиеся hex в CSS.

Старые коллекции ранних концепций не входят в контракт версии 1.2.0. Новый UI использует только четыре коллекции системы выше.

На широких экранах content max1056px центрируется в рабочей области. Внутри колонок обязательно `min-width:0`. Изменять ширину текста через Fill, высоту — через Hug. Экраны не масштабировать целиком.

Figma не переключает breakpoint автоматически: для смены структуры используются варианты Layout/Size и адаптивные примеры. В реализации переключение задают media queries в `smena-ui.css`. Автолейаут внутри выбранного варианта поддерживает изменение ширины и объёма контента.

### Таблицы, доска и граф

- Таблица использует единую схему колонок для шапки и строк. Реестр имеет минимальную ширину920px; на узком экране скролл находится внутри table viewport. Текст ячеек переносится. В макете строки находятся на canvas1056px; это reference-width, а не требование фиксировать всю страницу.
- Доска состоит из колонок с карточками FindingCard. На узком экране сохранять читаемую ширину колонки и горизонтальную прокрутку; не уменьшать текст карточек.
- Граф использует круглые SVG-узлы и тонкие связи на светлом поле. Размер viewport задаёт контейнер. Force layout вычисляется по данным, не по координатам из макета. Есть pan/zoom, поиск с переходом к узлу, фильтры, fit и полноэкранный диалог. Детали плавают справа, на узких экранах — снизу. Полные названия доступны в поиске и панели выбранного узла; узлы доступны с клавиатуры.
- Геометрия графа, SVG-линии и иконки — разрешённые исключения из Auto layout. Обычные UI-контейнеры используют Auto layout/Flex/Grid.

## Типографика и содержимое

Inter: display40/48 Bold; h1 32/40 Semi Bold; h2 24/32 Semi Bold; h3 18/26 Semi Bold; body15/24; small13/20; meta12/18; nav/button14/20 Medium. Полные значения — в token JSON и Text styles.

В frontend необходимо подключить Inter, предпочтительно локально из лицензированного font asset проекта. Системный fallback в CSS служит страховкой и не гарантирует совпадение метрик. Шрифт не включён в этот пакет UI kit.

Заголовки и основной текст переносятся. Длинным URL задаётся `overflow-wrap:anywhere`. В однострочном Input значение может обрезаться визуально или прокручиваться при вводе; полное значение хранится в input. Textarea многострочная. Подписи, ошибки, названия источников и ключевые действия не обрезаются.

Highlight используется для короткого ключевого фрагмента и сопровождается доступным источником. В коде это `<mark>` с `box-decoration-break:clone`, а не фон всей карточки. Tone=Uncertainty обозначает границу подтверждённого, а не ошибку сотрудника.

В Figma SourceCard, StepItem и FindingCard содержат вложенный Button `Action`; его Label и переход настраиваются на этом экземпляре. У Field значение меняется в `Control`. Не detach ради изменения текста или действия.

## Доступность и состояния

- Основной/вторичный текст и активные статусы имеют проверяемые цветовые пары. Muted и disabledText предназначены для неактивного состояния и декорации, не для важных инструкций.
- Focus — видимый контур2px. Disabled блокирует действие. Loading сообщает `aria-busy` и предотвращает повторную отправку.
- Сохранять текст задачи при ошибке. Показывать конкретную ошибку и способ повторить действие.
- Drawer: фокус внутрь при открытии; Escape закрывает; фокус возвращается на Menu. За модальной панелью фокус недоступен.
- Текст обязателен рядом с цветным статусом. Ошибки и неизвестное не обозначаются одним цветом.
- Использовать обычные button/a/input/label/table. SVG-иконки получают `aria-hidden`, когда подпись уже есть; иконке-кнопке необходим `aria-label`.
- Motion150ms; `prefers-reduced-motion` отключает переходы.

## Поддержка изменений

Каждая правка флоу обновляет затронутые main components, токены, примеры адаптации, manifest, руководство и changelog в одной версии. Порядок закреплён в `AGENTS.md` в корне проекта.

Patch — совместимые визуальные/документальные исправления. Minor — новый совместимый компонент или вариант. Major — переименование/удаление токена либо несовместимое изменение API. Для каждого релиза указывать затронутые компоненты, миграцию и фактические проверки.

Ветка передачи начинается с v1.0.0. В v1.1.0 основной пример переведён на бронирование концертного зала. Короткий срок взят из materials/DEMO.md бэка; это пересказ ожидаемого результата, а не дословная цитата оригинала. Оригиналы data/raw не опубликованы в репозитории. Цитаты, локаторы и source_id в продукте должны приходить из API. Пример конфликта и геометрия карты — демонстрационные состояния; реальные противоречия и нормативные зависимости не устанавливались.


## История 1.1.0: дополнительные маршруты

45 экранов продукта, 18 адаптивных примеров, 28 семейств / 135 компонентов и вариантов. Исходные ID экранов01–18 сохранены. В Figma есть три продуктовых старта и отдельная доска всех состояний. Подписи процесса находятся снаружи продуктовых фреймов.

Сотрудник: описание → поиск → ответ → источник → сохранение или замечание. Отдельные ветки: частичный ответ, отсутствие сведений, противоречие, недостаток контекста, ошибка сервиса и недоступный источник. Последовательного опроса сотрудника нет: для недостаточного контекста редактируется исходное описание.

Администратор: проверка ситуации → результат и карта → добавление источника → индексация → устаревший контрольный результат → повторная проверка. Успешный импорт не закрывает неподтверждённые вопросы. Форма файла показана до выбора, после выбора и после подтверждения открытости. Импорт содержит ожидание/чтение, успех, предупреждение, дубликат и ошибку. Остальные наблюдаемые этапы доступны в ProcessStatus.

Почта: журнал → настройки → сохранение или валидация; пауза → возобновление. Отдельно: ошибка ящика, недоступная панель, пустой журнал и тестовый режим. Письма в журнале имеют все семь состояний бота. Ручной повтор отправки и просмотр тела письма не добавлены: таких API в панели нет.

|---|---|---|

Ниже768px MailEvent переключается в Card. Все поля и результат видны без бокового скролла. На desktop/tablet сохраняется таблица. Не уменьшать размер текста ради размещения колонок. Прочие таблицы и граф могут прокручиваться внутри viewport.

### Формы и состояние запроса

- До выбора файла и подтверждения public_data запуск недоступен. Подтверждение — явное действие; нельзя отправлять public_data:true без него. replace_existing не включается автоматически.
- Файлы PDF/DOCX/XLSX до25МБ. Поле ссылки принимает поддерживаемый публичный файл/экспорт; HTML страницы и закрытые материалы не импортируются.
- Длинный вопрос: /api/ask — до20000 символов; общий проверяемый вопрос — до500. Обрезать ввод молча нельзя.
- Сохранять введённые значения при ошибке. Во время сохранения блокировать повтор, показывать Loading. После ответа показывать успех или ошибку; dirty-form не перезаписывать фоновым обновлением.
- Настройки бота: до100 полных адресов отправителей, один на строку. Пустой список разрешает всех отправителей. API — HTTPS без credentials/query/fragment, с ожидаемым путём. Пустой API включает тестовый ответ.
- Журнал и состояние бота обновляются каждые10с; ручное обновление не очищает данные. Состояние панели и worker.state различаются.

### Граница макета и бэка

Дизайн не подключает API и не отправляет почту. Подтверждённый контракт и необходимые доработки находятся в smena-backend-contract.md. Сохранение ответов и замечания сотрудника требуют frontend-хранилища/отдельного API; подтверждение владельцем и назначение исполнителей исключены из основного флоу. Code Connect добавляется после реализации настоящих компонентов.

Figma переходы из ожидания через1800мс служат только демонстрации. В продукте переход выполняется по фактическому SSE-событию или ответу status API; нельзя переносить таймер в логику приложения.


## Основной сценарий 1.2.0

[Описание задачи](https://www.figma.com/design/jORhjmSwUojzxk4ZGo9OI5?node-id=49-426) → загрузка → [план](https://www.figma.com/design/jORhjmSwUojzxk4ZGo9OI5?node-id=49-505) → конкретный этап → основание → отметки → продолжение → завершение. Вопросы-уточнения не образуют обязательный мастер перед планом. При недостатке контекста показывается честный результат API.

54 канонических экрана, включая два диалога;30 адаптивных примеров;30 семейств /138 компонентов и вариантов;114 токенов /12 текстовых стилей.92 технических кадра состояния прототипа учитываются отдельно от продуктовых экранов. Исходные ID01–18 сохранены.

План использует `answer.steps`. Каждый шаг имеет независимую отметку и собственные `citation_ids`; открытие источника не меняет отметки. Отметки можно ставить и снимать в любом порядке. «Продолжить» открывает первый невыполненный этап. «Готово» отмечает текущий этап и открывает следующий. «Завершить» доступно только при наличии шагов и выполнении всех. Завершение означает пользовательскую отметку; статус кадровой операции проверяется во внешнем сервисе.

ProgressSegment использует `layout/progress-track-height`, `progress/track`, `progress/fill`; новые переменные не дублируют семантические цвета. StepItem сохраняет исходные варианты и IDs; добавлены boolean Show completion и Show number. Текст каждого основания передаётся в EvidenceCard; action открывает точный source_id. Диалог обратной связи не разрушает состояние лежащей под ним задачи.

В Starter недоступны SET_VARIABLE и несколько действий на событие. Для всех16 сочетаний отметок в Figma построены навигационные состояния. Это конструкция прототипа: во frontend применяются обычные данные задачи и переиспользуемые компоненты, без92 копий экранов.

Публичный демонстрационный источник: [«Оформление нового подразделения и сотрудников», МФТИ HR2024, страница1, этап6](https://mipt.ru/docs/download.php?code=instruktsiya-oformlenie-novogo-podrazdeleniya-i-sotrudnikov#page=1). Он проверен отдельно, не входит автоматически в20 материалов Git и не подтверждает состояние текущего индекса. Перед реальной демонстрацией этого сценария его нужно разрешённо импортировать. Подробная инструкция по должностным инструкциям находится на внутреннем портале; её содержимое не придумывается.

## Реализация frontend

В отдельной ветке `codex/smena-frontend` реализовано React19/Vite приложение с исходными токенами этой системы. Steps и citations приходят из FastAPI. Прогресс хранится в браузере (до50 задач); запрос материалов сохраняется в серверной очереди. UI SDK управляет модальными окнами; Cult UI используется для поиска и настроек отображения. Настройки отображения не изменяют системный промпт RAG. Реальные файлы компонентов указаны в manifest; официальные Code Connect связи не создаются без проверки сервиса Figma.

## Исправления интерфейса 1.3.0

Frontend и контракт обновлены 14 ноября 2026. Нативная Figma остаётся на 1.2.0: файл «Смена» отключён от Local Bridge, открыт другой проект. Синхронизация помечена pending_connection в manifest и карте состояния. Новые Figma IDs и пройденная нативная QA не заявляются.

- Основания плана и этапа идут полными строками под основным содержимым. Каждый источник сначала закрыт; раскрывается кликом, Enter или Space. Внутри цитата с mark и кнопка точного source_id. Длинные названия и локаторы переносятся.
- Составное текстовое поле имеет одну внешнюю рамку focus-visible. Вложенный input/textarea не рисует внутренний outline или shadow. Клавиатурный фокус не убирается. Обычный одиночный input имеет внешний outline с offset3.
- Checkbox имеет только On/Off; повторное нажатие снимает отметку сразу. Hover/active не меняют яркость. Disabled остаётся отдельным состоянием. Минимальная область нажатия label44px.
- Между текстом источника и действием20px, в группах действий16px, текст шага и его действие16px. Перенос кнопок не сжимает эти интервалы. Типографика и цвета используют прежние114 токенов; новые дубли переменных не создавались, экспорт и generated CSS не изменялись.
- Каталог открывает DocumentReader. GET /api/documents/{id}?corpus_revision=… возвращает все извлечённые блоки выбранной версии, локаторы и предупреждения. Это текст из индекса; исходный PDF/DOCX/XLSX не имитируется. При смене корпуса —409 и сообщение обновить каталог; отсутствующий документ —404, недоступная база —503.
- GraphExplorer показывает только реальные принадлежности document↔topic, смысловые связи topic↔topic и результаты question↔topic. Смысловая близость не является нормативной зависимостью, not_found не доказывает дефект регламента. Все узлы доступны через поиск; круги поддерживают Enter/Space. Поле: стрелки — перемещение, +/− — масштаб, 0 — показать всё. Колесо масштабирует относительно курсора, Esc закрывает полный экран.
- Официальный логотип МФТИ используется без перерисовки и перекраски. «Смена» остаётся названием продукта. Иллюстрации оригинальные, с научными мотивами; декоративные изображения имеют alt="". Происхождение и описания генерации — frontend/public/illustrations/asset-manifest.json. Прежние заимствованные картинки Notion удалены.

Проверки frontend: production build,7 unit-тестов,22 браузерных сценария с синтетическим сервером; ширины320/390/1024/1440/1920. Нативные автолейауты и переходы Figma в этой версии не изменялись и заново не проверялись. Проверки UI не подтверждают качество RAG на реальном корпусе.
