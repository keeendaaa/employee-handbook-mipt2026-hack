## Ограничения на момент проверки

- В исходном извлечении 11 документов имеют предупреждения: OCR, сложные PDF-таблицы, непроверенные сохранённые значения формул и повреждённая ссылка Excel. Это частичный успех извлечения, а не полная обработка без потерь.
- Qwen вызывается как `Qwen/Qwen3.8-27B` через Command Code; локальный Qwen 8B на VPS не запущен. E5 работает на CPU внутри VPS.
- При финальной проверке генерации Command Code возвращал **HTTP 503 `overloaded_error`** как с Mac, так и с VPS, на обоих документированных endpoint. Рабочий ответ Qwen через опубликованный VPS на этот момент не подтверждён. Сервис выполняет одну повторную попытку и возвращает явную техническую ошибку HTTP 502; поиск остаётся доступным.
- Идентификаторы и текст цитат проверяются программно; смысловое соответствие вывода источнику оценивает модель. Автоматическое разрешение редакций и независимая проверка всех процедур не выполнены.
- Демонстрация опубликована по HTTP. Данные, пароль PostgreSQL и ключ API исключены из Git и Docker-образа; оригиналы размещены на VPS по разрешению пользователя.

Инструкция повторения: [DEPLOY.md](DEPLOY.md). Для внешней проверки используйте `uv run python misc/scripts/smoke_http.py http://178.20.47.178 --question 'Ваш вопрос'`; флаг `--ask` дополнительно проверяет генерацию и расходует API-кредиты.

После завершения локальных проверок API, PostgreSQL, временные браузеры и SSH-туннель остановлены, Docker Desktop выключен. Данные PostgreSQL сохранены в volume.

Тестовый проект, его база и временные контейнеры удалены.

На мобильной ширине 390 px не обнаружены горизонтальная прокрутка и ошибки JavaScript.

После переключения образа в реальном Chrome повторены межфайловый переход, открытие цитаты, выбор общего вопроса и мобильная проверка; ошибок JavaScript нет, контрольная сумма загруженного JavaScript совпадает с финальным исходником. ## Проверка надёжности ответа и холодной карты — 13.11.2026

При `not_found` сервер заменяет свободные пояснения модели одним сообщением о том, что ответ не подтверждён в найденных фрагментах. Результат не допускает фактических утверждений, уточнений или конфликтов в других полях. Частичный ответ сохраняет описание конкретных пробелов. Это ограничение формы ответа, а не доказательство отсутствия сведений во всей базе.

Если группировка тем завершилась во время генерации, поток дополняется событием `map_update` для прежней выдачи и прежнего корпуса. Регрессионные тесты проверяют порядок событий, сохранение идентификаторов источников и однократность поиска и генерации. Смена корпуса и техническая ошибка карты не мешают вернуть готовый ответ и не создают связи с другой версией базы.

Размер карты проверяется отдельным SQL-подсчётом до чтения документов и векторов. Тесты для пустого корпуса и 20 001 фрагмента запрещают вызов методов загрузки содержимого; интеграционный тест проверяет подсчёт для двух неизменяемых корпусов и отсутствующего ключа.

На Mac: **140 passed, 5 skipped**; пропуски требуют PostgreSQL. В контейнере кандидата на VPS с отдельной временной БД: **145 passed**, без пропусков; временная БД удалена. Проверка синтаксиса JavaScript и `git diff --check` пройдены. Предупреждение AnyIO в TestClient не является ошибкой теста. Вторичная проверка через pi завершилась по тайм-ауту без отчёта и не учитывается как успешный аудит.

После обновления публичный HTTPS-поток проверен двумя реальными запросами к настроенному API модели. При холодной карте выдача пришла со статусом `building`, затем до ответа получено одно событие `map_update` со статусом `ready`. Корпус, состав источников и бюджет доказательств сохранились. Вопрос о бронировании концертного зала получил `answered` с двумя цитатами; вопрос о заявке на отпуск — `not_found` без цитат и с фиксированным ограниченным сообщением. Запросы не добавились в общую карту: осталось две ранее опубликованные проверки. Отчёты и записи SSE находятся в игнорируемом `data/review/`, а не в Git. Версия рабочего корпуса не изменилась; образ и исходники до обновления сохранены на VPS для отката.

В обычном Chrome сначала воспроизвелось зависание запроса карты при объявленном HTTP/3. Диагностический запуск с отключённым QUIC прошёл успешно. После настройки Caddy на HTTP/1.1 и HTTP/2 проверка обычным Chrome без специальных сетевых флагов также прошла: реальный поиск, открытие точных строк, отсутствие ошибок JavaScript и горизонтальной прокрутки на ширине 390 px. Конфигурация Caddy проверена `caddy validate` и применена через reload с резервной копией; существующий тайм-аут прокси сохранён. Первоначальная браузерная проверка с зависшим запросом не засчитана как успешная.

Финальная правка интерфейса убирает общее утверждение об отсутствии сведений «в документах» и оставшуюся после завершённой выдачи подсказку ожидания.
