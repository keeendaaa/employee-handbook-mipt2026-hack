# Запуск демонстрации

Фактический профиль: CPU `intfloat/multilingual-e5-small` (384 измерения, фиксированная ревизия в `embedding.py`), PostgreSQL 17 + pgvector, FastAPI и внешний `Qwen/Qwen3.8-27B` через Command Code. Веса Qwen на VPS не скачиваются. Локальный Qwen 8B остаётся вариантом развития, в этой конфигурации он не запускается.

Рекомендуемые ресурсы для текущего комплекта: 4 vCPU, 8 ГБ RAM, от 15 ГБ свободного диска; GPU не нужен. Нужен интернет для сборки, загрузки E5 и вызовов API. Инференс эмбеддингов после скачивания работает офлайн. API модели оплачивается отдельно.

## Подготовка

Установите Docker с Compose v2. Скопируйте `.env.example` в `.env`, задайте уникальный пароль PostgreSQL из букв и цифр. Для CLI вне контейнера укажите тот же пароль в `DATABASE_URL`. Секреты и материалы не входят в Docker-образ.

```sh
mkdir -p secrets data/raw data/processed models
chmod 700 secrets
# Запишите ключ Command Code в secrets/llm_api_key редактором, без помещения в историю shell.
chmod 600 secrets/llm_api_key
chmod 600 .env
docker compose build
docker compose up -d postgres
docker compose run --rm ingest download-model
docker compose run --rm ingest db-init
```

Поместите разрешённые к обработке PDF/DOCX/XLSX в `data/raw/`. Не отправляйте конфиденциальные документы во внешний API без разрешения. `data/manifest.json` необязателен для нового комплекта; для исходного комплекта используйте его при импорте для сохранения идентификаторов.

```sh
docker compose run --rm ingest ingest --manifest data/manifest.json --allow-warnings
# Для произвольного комплекта без manifest: ingest --allow-warnings
# --allow-warnings допускает неполное извлечение, сохраняя предупреждения в отчёте.
# Изучите data/processed/report.json перед демонстрацией.
docker compose up -d api import-worker
curl --fail http://127.0.0.1:8000/health/ready
```

Для VPS установите `HTTP_BIND=0.0.0.0` и `HTTP_PORT=80` в `.env`. Страница доступна по адресу сервера. Это HTTP-демонстрация; для HTTPS нужен отдельный прокси и сертификат. PostgreSQL публикуется только на loopback `127.0.0.1:5433`.

### Домен и HTTPS на VPS

Конфигурация Caddy находится в `misc/deploy/Caddyfile`: основной домен `smena-mipt.ru`, перенаправление с `www.smena-mipt.ru` и сохранение HTTP-доступа по IP. Для обоих имён нужны DNS-записи A со значением `178.20.47.178`.

При использовании прокси задайте в закрытом `.env` `HTTP_BIND=127.0.0.1`, `HTTP_PORT=8000`. Узнать шлюз Docker-сети можно командой `docker inspect navigator-api-1 --format '{{range .NetworkSettings.Networks}}{{.Gateway}}{{end}}'`; это значение укажите в `FORWARDED_ALLOW_IPS` (на текущем VPS — `172.18.0.1`). Приложение доверяет заголовкам адреса клиента только от этого шлюза, чтобы лимиты запросов различали посетителей. Порт приложения публикуется только на loopback.

На VPS, из корня проекта:

```sh
sudo apt-get install -y caddy
sudo install -m 644 misc/deploy/Caddyfile /etc/caddy/Caddyfile
sudo caddy validate --config /etc/caddy/Caddyfile
docker compose up -d api import-worker
sudo systemctl enable --now caddy
# После изменения конфигурации:
sudo systemctl reload caddy
```

Снаружи должны быть доступны TCP 80 и 443. Caddy [автоматически получает и обновляет сертификаты](https://caddyserver.com/docs/automatic-https) после публикации DNS. Добавление записей в панели регистратора само по себе ещё не подтверждает доступность домена: проверяйте публичное разрешение имён и HTTPS без отключения проверки сертификата.

Если извлечение уже выполнено этой версией кода, его можно проверить и индексировать без повторного OCR:

```sh
docker compose run --rm ingest index --report data/processed/review-v2/report.json --input data/raw --allow-warnings
```

Оригиналы должны совпадать с SHA-256 отчёта. Новые файлы добавляются повторным `ingest`, без изменения кода. Ссылки на старые поколения сохраняются.

## Загрузка документов из интерфейса

Панель «Добавить документы» на главной странице принимает PDF, DOCX и XLSX до 25 МиБ каждый, до пяти файлов за отправку, а также публичную HTTP/HTTPS-ссылку на файл. Новые документы попадают в **общую базу для всех посетителей**. Перед отправкой нужно подтвердить неконфиденциальность: найденные фрагменты могут передаваться внешней модели при ответе.

Поддерживаются прямые ссылки и открытые ссылки Google Drive, Docs и Sheets с экспортом в поддерживаемый формат. Страницы сайтов, ссылки с авторизацией и внутренние адреса не импортируются. Ошибка доступа отображается в статусе задачи; она не означает, что документ обработан.

`import-worker` читает документы и строит эмбеддинги локально в фоне. Ключ внешней модели ему не передаётся. Очередь и статусы хранятся в PostgreSQL, оригиналы и результаты извлечения — в `data/imports/`; этот каталог нужно сохранять при обновлении и включать в резервную копию. Первоначальный индекс должен быть создан командами выше. После изменения схемы выполните `docker compose run --rm ingest db-init` перед обновлением API.

Идентичные байты повторно не индексируются. Другой файл с тем же именем по умолчанию отклоняется; флажок обновления явно разрешает заменить его в активной базе. Это решение пользователя, а не автоматическое определение юридической актуальности. Старые версии и ссылки на цитаты сохраняются. Добавление публикует индекс атомарно, повторно вычисляя эмбеддинги только нового документа.

Статусы различают ожидание, скачивание, извлечение/OCR, индексирование, успех, частичный успех с предупреждениями и ошибку. Закрытие страницы не отменяет обработку; браузер запоминает последние идентификаторы задач. Лимиты демо: 10 попыток импорта в час на IP, 40 принятых задач в сутки на всю базу, до пяти незавершённых задач, до 2000 новых фрагментов на документ. При недоступности обработчика новые задачи отклоняются с HTTP 503.

## Общая карта знаний

`GET /map` открывает интерактивный граф для всех пользователей демонстрации. На главной странице есть ссылка на него. Авторизация не добавляется; доступ совпадает с доступом к существующему демо.

Карта читает реальные 384-мерные E5-векторы из активного снимка PostgreSQL. Локальный MiniBatchKMeans объединяет фрагменты по смыслу, без разделения по исходным файлам. Названия групп — автоматически выделенные TF-IDF-слова, а не утверждения об области действия регламента. Темы связываются с тремя ближайшими центрами по cosine similarity; D3 располагает этот граф в браузере. Расстояние на экране не является точной мерой сходства. D3 7.9.0 включён локально с лицензией, обращения к CDN при просмотре не нужны.

При выборе темы показываются её документы и до 40 фрагментов, ближайших к центру. Выбор фрагмента открывает граф восьми ближайших соседей **по всему корпусу** и позволяет открыть точную цитату с подсветкой строк. Отбор соседей выполняется в исходных 384 измерениях, а не по расстоянию на картинке. Цвет фрагмента обозначает документ.

«Проверить и добавить на карту» вызывает существующий RAG-процесс с теми же лимитами генерации. Вопрос и проверенный результат становятся общими только после явного подтверждения неконфиденциальности и публикации. Результаты `not_found` отображаются пустыми узлами как «в найденных фрагментах ответ не найден»; частичные ответы и противоречия различаются с полными ответами. Сходство фрагментов и геометрическое пустое место не классифицируются как пробел. Ошибка модели, сети или БД возвращается технической ошибкой и не сохраняется как нехватка знаний.

Проверки хранятся в PostgreSQL вместе с версией корпуса, временем и точными источниками. После импорта карта перестраивается при следующем открытии или обновлении; прежние проверки помечаются как требующие повторной проверки. Повторный запрос для того же вопроса и поколения обновляет запись без дубля. Проверки не запускаются автоматически после импорта и не расходуют API-кредиты без действия пользователя.

Построение карты выполняется одним фоновым потоком API, результат кэшируется по ключу корпуса. Поиск продолжает работать во время построения. Для демонстрации установлены пределы: 20 000 фрагментов карты и 500 различных общих вопросов. Количество фрагментов проверяется до загрузки векторов и текстов карты в память. Превышение лимита карты не отключает обычный поиск. Построение карты не вызывает LLM, эмбеддинги документов не пересчитываются. NumPy, scikit-learn и threadpoolctl закреплены как прямые зависимости; они уже входили в окружение embedding-модели.

При обновлении пересоберите образ и примените схему перед перезапуском:

```sh
docker compose build api ingest import-worker
docker compose run --rm ingest db-init
docker compose up -d api import-worker
```

## Живая карта на странице поиска

На главной странице под вопросом размещена карта текущего запроса. Она получает события подготовки смыслового представления вопроса, гибридного поиска и генерации через SSE. После получения выдачи области раскрываются в фактические фрагменты; зелёным отмечаются только канонические идентификаторы цитат из готового ответа. «Темы», «Фрагменты» и «Весь контекст» позволяют менять уровень детализации. Источник открывается с точной подсветкой строк. Отображение учитывает настройку уменьшения движения.

`POST /api/query/stream` принимает `{"question":"…","mode":"ask","limit":10}`; `mode:"search"` выполняет только поиск. Ответ имеет тип `text/event-stream`. Каждая запись `data:` содержит JSON с `type`: `started`, `stage`, `retrieval`, `map_update`, `answer`, `search_complete`, `done` или `error`. До начала потока ошибки валидации возвращаются обычным HTTP-ответом; после начала потока техническая ошибка передаётся событием `error` с `status_code` и `detail`. Получатель должен проверять событие завершения, а не только HTTP 200. Пустой результат поиска, техническая ошибка и результат оценки ответа различаются.

Обычные `/api/search` и `/api/ask` сохраняют прежние JSON-контракты. Поток использует те же блокировки, лимиты вызова модели, поиск, бюджет контекста и генератор. Поиск выполняется по общему индексу; карта группирует фактическую выдачу. Цвет кандидата не доказывает наличия ответа. События содержат только наблюдаемые этапы обработки и точные ссылки на источники. Дополнительных вызовов LLM или повторного вычисления эмбеддингов документов для визуализации нет. Если группировка закончилась во время генерации, событие `map_update` перед ответом дополняет прежнюю выдачу темами того же корпуса. Смена корпуса или ошибка карты не прерывает ответ и не добавляет связи с другой версией базы.

Вопрос на странице поиска остаётся в рамках запроса и автоматически не публикуется в общей карте `/map`. При недоступности группировки тем показываются фактически найденные фрагменты, обычный ответ продолжает формироваться. Отмена закрывает клиентский поток и прекращает последующие этапы; синхронный запрос к провайдеру, уже отправленный до отмены, может завершиться на сервере. После разрыва передачи неполный результат не объявляется готовым ответом.

Для `not_found` сервер возвращает одно ограниченное сообщение: «В найденных фрагментах не удалось подтвердить ответ на вопрос». Дополнительные неподтверждённые пояснения модели удаляются; это не доказывает отсутствие ответа во всей базе. У частичного ответа сохраняется описание конкретных пробелов.

## API и проверка

- `GET /` — страница вопроса, ответа, шагов и источников.
- `GET /map` — общая карта знаний.
- `GET /api/map` — темы, смысловые связи и общие проверенные вопросы; HTTP 202 означает фоновое построение, технический сбой возвращает HTTP 503.
- `GET /api/map/topics/{topic_id}?corpus_revision=…` — фрагменты выбранной темы.
- `GET /api/map/fragments/{chunk_id}?corpus_revision=…` — ближайшие соседи фрагмента и ссылки на источники. Для устаревшей версии карты возвращается HTTP 409.
- `POST /api/map/questions` — `{"question":"…","public_data":true}`, проверка и публикация результата; максимум 500 символов, HTTP 201. Секреты и сырые векторы вопросов в ответах карты не возвращаются.
- `GET /health/live` — процесс запущен.
- `GET /health/ready` — доступен активный индекс; `generation_configured` сообщает только о настройке генерации, а не о текущем балансе или доступности внешнего API.
- `POST /api/search` — `{"question":"…","limit":10}`, поиск без вызова LLM.
- `POST /api/ask` — такой же запрос, ответ `answered/partial/not_found/needs_clarification/conflict`, утверждения и шаги с `citation_ids`, канонические `citations`, фактическая модель и расход токенов.
- `POST /api/imports/file` — multipart: `file`, `public_data=true`, необязательный `replace_existing=true`; HTTP 202 и идентификатор задачи.
- `POST /api/imports/url` — JSON: `{"url":"https://example.org/file.pdf","public_data":true,"replace_existing":false}`; HTTP 202.
- `GET /api/imports/{job_id}` — статус, предупреждения и идентификатор опубликованного индекса, без исходной ссылки и её параметров.
- `GET /api/sources/{source_id}` — точная цитата и полный извлечённый блок с координатами. Строки относятся к извлечённому блоку, а не к строкам оригинального PDF. OCR-пункты не считаются проверенными.

Каждое утверждение должно ссылаться на существующие источники. Сервер проверяет структуру и идентификаторы и берёт цитаты из индекса; смысловое соответствие оценивает Qwen, поэтому ссылка сама по себе не гарантирует истинность вывода. Отсутствующий ответ и техническая ошибка различаются. Существующие предупреждения извлечения, актуальность редакций и полнота процедуры требуют отдельной оценки.

Для воспроизводимого синтетического примера создайте файлы командой `uv run python code-samples/make_documents.py` по инструкции `INGEST.md` и спросите про тестовое правило, действительно записанное в файле. Два сценария на реальном разрешённом комплекте: вопрос о сроке подачи служебной записки для бронирования концертного зала → срок с цитатой и оговоркой о найденных исключениях; вопрос о первой линии техподдержки → разрешённые каналы обращения с цитатами. Содержание ответа проверяется по фактически загруженным редакциям, а не задаётся в коде.

Один процесс API обслуживает по одному поиску и генерации одновременно. Лимит публичной демонстрации: 15 попыток генерации в час на IP и 60 в час на процесс; перезапуск сбрасывает счётчики. Поиск доступен без LLM. Qwen использует `reasoning_effort=low`, лимит вывода 10000 токенов (включая рассуждение). Таймаут одного запроса к модели 120 секунд, при некорректном формате или временной HTTP-ошибке 500/502/503/504 возможна ещё одна попытка (всего не более двух вызовов). Данные и ключ не отправляются в браузер; тексты запросов не пишутся в access log.

Оценка стоимости для `Qwen/Qwen3.8-27B`: $0.40 за миллион входных и $3 за миллион выходных токенов, без скидок кэша; `usage.cost_usd_estimate` — оценка, не счёт провайдера. Тариф необходимо перепроверять у [Command Code](https://commandcode.ai/models/qwen3-8-27b).

```sh
uv sync --frozen
uv run pytest -q
# Интеграционные тесты БД: TEST_DATABASE_URL=… uv run pytest -q
# Остановка без удаления данных:
docker compose down
# Обновление кода:
docker compose build api import-worker
docker compose up -d api import-worker
```

Не выполняйте `down -v`, если требуется сохранить индекс. Для резервирования нужны `pg_dump`, оригиналы, отчёты извлечения и веса E5; ключ и `.env` хранятся отдельно с закрытыми правами.

Проверка опубликованного HTTP-сервиса без вывода содержимого документов:

```sh
uv run python misc/scripts/smoke_http.py http://127.0.0.1:8000 --question 'Ваш вопрос'
# --ask дополнительно вызывает платную генерацию и проверяет все возвращённые ссылки.
```
