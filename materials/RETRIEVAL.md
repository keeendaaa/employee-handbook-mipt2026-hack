# Поиск и цитаты до подключения Qwen

Реализованы поиск кандидатов и проверка точности цитат. Генерация ответа, семантическое подтверждение вывода, автоматический отказ, разрешение применимости редакций и HTTP API пока отсутствуют.

## Подготовка и запуск

Модель и окружение подготавливаются по [INGEST.md](INGEST.md). Новые возможности доступны после `docker compose build ingest`. Все команды работают локально.

```sh
docker compose up -d postgres
docker compose run --rm -v ./data/manifest.json:/app/manifest.json:ro ingest extract --manifest /app/manifest.json --output data/processed/review-v2 --timeout 900
docker compose run --rm ingest audit --report data/processed/review-v2/report.json --output data/processed/extraction-audit.json
docker compose run --rm ingest index --report data/processed/review-v2/report.json --allow-warnings
docker compose run --rm ingest search "Как обратиться в техподдержку и кто отвечает за приложения в ЦОД?" --limit 10 --output data/processed/search.json
```

`extract` может завершиться кодом 2: это явный частичный успех, детали в отчёте. `index` требует явного разрешения предупреждений и проверяет SHA-256 оригиналов и целостность извлечённых артефактов. Тяжёлый OCR повторять для каждого изменения поиска не требуется. При ошибке активный индекс сохраняется.

Для просмотра цитаты возьмите `results[].citation.source_id` из результата поиска:

```sh
docker compose run --rm ingest source '<source_id>' --output data/processed/source.json
```

Не подставляйте `<source_id>` буквально: это значение из конкретного результата. Команда работает без модели и возвращает прежнюю версию блока даже после обновления активного корпуса. Этот контракт используется кнопкой открытия основания и HTTP-обработчиком `/api/sources/{source_id}`; текущий запуск описан в [DEPLOY.md](DEPLOY.md).

## Что изменено в поиске

- Прямой вопрос сохраняется; составной дополнительно разделяется по границам подвопросов. Длинный текст разбивается на окна по токенизатору E5 с перекрытием, без молчаливого усечения конца. Повторяющиеся части вычисляются один раз.
- Все подзапросы используют один неизменяемый корпус и совместимую модель. Выдача объединяется через RRF, резервирует кандидата для каждой части и ограничивает повторение одного исходного блока. `unrepresented_query_parts` явно перечисляет части без кандидата в итоговом бюджете. Наличие кандидата не доказывает покрытие вопроса.
- При явном номере приказа, распоряжения или регламента выполняется ограниченный лексический добор внутри документов с совпавшим реквизитом в имени. Номер используется как поисковая подсказка и исключается из текстового запроса добора; это не подтверждение актуальности. Ранжирование добора учитывает число разных совпавших слов, а не только частоту. Повторный маршрут не усиливает уже найденные глобальные кандидаты; общий поиск сохраняется. Если имя не позволяет распознать реквизит, поиск продолжает работать без этой подсказки.
- В embeddings добавлены название документа и путь раздела в пределах 512 токенов. `embedding_text` хранится отдельно; цитируемый `text` остаётся точным срезом блока. Изменение обработки создаёт новые chunk/corpus ID.
- Для проверки условий добирается ограниченный контекст самого блока и соседних абзацев/строк таблицы. Контекст имеет собственные точные цитаты, не склеивается с исходным фрагментом и учитывается отдельной метрикой.
- Поиск возвращает `retrieval_status` и `answer_status: not_assessed`. Даже при тематической выдаче нельзя объявлять нормативный ответ найденным. Ошибки БД/модели не маскируются отказом.

Исходный алгоритм доступен через `search --baseline`; компоненты текущего поиска — через `--mode dense`, `lexical`, `hybrid`.

## Привязка к пунктам и строкам

Каждая цитата содержит `source_id`, `document_id`, `version_id`, `document_name`, `original_sha256`, `locator`, `block_index`, `start`, `end`, `quote`, `line_start`, `line_end`, `line_basis` и `section_labels`.

`quote` в точности равен срезу блока `[start:end]`. Строки нумеруются **в неизменяемом извлечённом блоке**, а не выдаются за строки исходной вёрстки. PDF-страница, лист/диапазон XLSX или блок DOCX передаются отдельным локатором. Номер пункта берётся из явно присутствующей нумерации; отсутствующий номер не восстанавливается предположением. Для OCR действует отметка `ocr_unverified`.

Интерфейс сможет показать название, пункт/страницу, точную цитату, выделение диапазона строк и действие открытия по `source_id`. При отсутствии номера пункта нужно показывать доступный локатор. Проверка `sources.verify` обнаруживает подмену текста, смещений, локатора и версии; она **не доказывает**, что цитата по смыслу подтверждает будущий вывод модели.

## Воспроизводимая оценка

Реальный набор `data/review/eval/questions.json` хранится локально: 35 вопросов, все 20 документов, 27 рабочих и 8 отложенных вопросов. Для каждого указаны ожидаемый тип ответа, конкретные документы/локаторы/текстовые якоря и обязательные факты. Это агентская разметка по прочитанным источникам, без независимой проверки человеком. Отрицательные метки также требуют проверки; они не считаются автоматически пройденными.

```sh
docker compose run --rm -v ./data/review/eval/questions.json:/app/questions.json:ro ingest evaluate --dataset /app/questions.json --split dev --k 10 --output data/processed/eval-dev.json
docker compose run --rm -v ./data/review/eval/questions.json:/app/questions.json:ro ingest evaluate --dataset /app/questions.json --split holdout --k 10 --output data/processed/eval-holdout.json
```

Отчёт фиксирует корпус/модель, хеш набора, время, Recall@k по документам и якорям, MRR, покрытие всех оснований, доступность якорей и технические ошибки. Название документа само по себе не считается попаданием в основание: проверяются локатор и текст. Качество сформированного ответа и корректность отказа пока не оцениваются.

Наблюдаемые результаты на локальном комплекте, 12.11.2026:

| Проверка при k=10 | Документы | Основания в фрагментах | С контекстом | Ошибки запросов |
|---|---:|---:|---:|---:|
| Исходный поиск, рабочие вопросы | 96% | 26/31 (83,9%) | 26/31 | 1: длинный вопрос |
| Текущий поиск/индекс, рабочие вопросы | 100% | 28/31 (90,3%) | 30/31 (96,8%) | 0 |
| Текущий поиск/индекс, 8 отложенных вопросов | 100% | 100% | 100% | 0 |

После первого контрольного прогона параметры под эти восемь вопросов не подбирались. Набор небольшой, результаты не являются официальной оценкой жюри или гарантией качества новых вопросов. Сравнение исходного/текущего поиска включает одновременно исправление извлечения, изменение embeddings и поиск; это не изолированная оценка одной техники. ### Исправление R13 — 13.11.2026

Нужный фрагмент присутствовал среди кандидатов одного подвопроса, но терялся при объединении с общей тематической выдачей. Ограниченный добор по указанному реквизиту сохраняет точное основание без подстановки готового ответа или специальных правил для конкретного документа.

Повторная проверка всего набора на том же корпусе: 35 вопросов, 33 с размеченными основаниями, 2 отрицательных без оценки автоматического отказа. При k=10 найдены все ожидаемые документы, 39/41 основания непосредственно в фрагментах и 41/41 с контекстом; технических ошибок нет. Прежний промах `R13` теперь находится на первой позиции. Прямое попадание без контекста остаётся неполным у `R16`; его основания доступны в соседнем контексте.

Старые отчёты сохранены в `data/review/eval/improved-*-before-r13.json`; общий повторный прогон — `improved-all.json`. Восемь отложенных вопросов проходят повторную регрессионную проверку; это уже использовавшийся контрольный набор, а не новая независимая выборка.

Исходный вопрос и три перефразирования проверены при k=5: основание каждый раз на первой позиции, цитаты открываются точно по сохранённым смещениям. После исправления прошли 63 теста с PostgreSQL. В обновлённом Docker-образе отдельно воспроизведены первая позиция `R13` при limit=5 и открытие той же цитаты по `source_id`.

Синтетический пример для клонированного репозитория генерируется командой `uv run python code-samples/make_documents.py`: документы и `data/processed/demo-cases.json`. Индексируйте его в отдельную БД, затем запускайте `evaluate --dataset data/processed/demo-cases.json --split dev`. Успех этого примера не подтверждает качество на реальной базе.

## Проверка предупреждений

Локальный аудит подтверждает комплект 9 PDF + 8 DOCX + 3 XLSX. Новое извлечение: 48 OCR-страниц, два исправленных поворота на 90°, одна повреждённая ссылка `#REF!`, 854 формулы без доступного сохранённого значения. Расчёт формул не выполнялся. Выборочно визуально просмотрены семь PDF-страниц; это не полная визуальная сверка всех документов.

Опубликованы 2923 фрагмента; старые версии сохранены. У 11 файлов остаются ограничения, поэтому статус корпуса остаётся `partial`. Не закрыты полная проверка PDF-таблиц/сложной нумерации, независимая разметка, применимость редакций, полнота процедур и смысловая проверка будущих ответов. Эти ограничения должны оставаться видны при подключении Qwen.

В визуальной выборке также зафиксирована остаточная OCR-ошибка в аббревиатуре исполнителя; автоматическая «догадка» вместо текста не применялась. Подробности — в локальном `data/review/eval/visual-review.json`.

На финальном коде прошли 56 тестов с PostgreSQL, включая изоляцию поколений и сохранность цитат. В собранном Docker-образе воспроизведены составной поиск, открытие точного фрагмента через `source_id` и контрольная оценка восьми вопросов. Qwen не скачивался и не запускался.
