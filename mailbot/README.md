# Почтовый бот Навигатора

Бот читает новые письма из Timeweb через IMAP STARTTLS на порту 143. Он передаёт вопрос в `POST /api/mail/analyze`. Из ответа формирует письмо с шагами, уточнениями и проверяемыми цитатами. Отправляет его в исходную цепочку через SMTP STARTTLS на порту 587. Для вызова Навигатора нужен исходящий HTTPS и сертификат, которому доверяет контейнер.

## Запуск

Нужны Docker с Compose и отдельный почтовый ящик Timeweb. Из корня репозитория перейди в каталог бота:

```sh
cd mailbot
cp .env.example .env
mkdir -p data secrets
chmod 700 data secrets
```

В `.env` задай адрес ящика в `MAILBOT_ADDRESS` и адрес Навигатора в `MAILBOT_API_URL`. Введи пароль через скрытый запрос. Команда создаёт новый файл секрета с правами `0400`.

```sh
python3 - <<'PY'
import getpass
import os

password = getpass.getpass("Пароль ящика Timeweb: ")
if not password:
    raise SystemExit("Пароль пуст")
os.umask(0o377)
with open("secrets/mail_password", "x") as secret:
    secret.write(password)
PY
```

На Mac с Docker Desktop запусти:

```sh
export MAILBOT_UID="$(id -u)" MAILBOT_GID="$(id -g)"
docker compose -f compose.yaml -f compose.local.yaml up -d --build
```

На Linux используй базовый Compose. Контейнеры работают с UID и GID 10001.

```sh
sudo chown 10001:10001 data secrets/mail_password
docker compose up -d --build
```

Панель доступна по адресу <http://127.0.0.1:8787/>. На удалённой машине используй SSH-туннель к этому адресу. В панели можно приостановить бота, ограничить отправителей и изменить API. Пустой список разрешает любые адреса. Настройки из панели сохраняются в SQLite и имеют приоритет над исходным URL из `.env`. По умолчанию бот пропускает письма, где помощь не нужна. В панели можно включить подтверждение их получения. Пустой URL в панели включает тестовый ответ без анализа.

При первом запуске бот начинает с новых писем. Один ящик обслуживает один обработчик. Для остановки используй `docker compose stop`, передав те же Compose-файлы, что при запуске. Данные хранятся в `data/`.

## Проверка по почте

Отправь вопрос обычным текстом письма. Навигатор может передавать его внешней модели, поэтому используй открытые вопросы без конфиденциальных данных. Разовое ознакомление с этим условием через профиль пользователя пока не реализовано.

```text
Где в открытых материалах указан порядок обращения в первую линию техподдержки?
```

При наличии подходящего материала бот пришлёт ответ со ссылками на фрагменты. Второй сценарий — вопрос, сведения о котором отсутствуют в тестовом корпусе. Ответ сообщит, что в найденных фрагментах сведений нет. Каждый запрос обрабатывается отдельно. Для уточнения сформулируй полный вопрос с нужным контекстом. Бот передаёт API тему и извлечённый текст. Адрес отправителя, HTML-разметка и вложения в запрос не входят. Бот извлекает текст из обычных и HTML-писем.

При HTTP 429, временной ошибке Навигатора или сбое сети бот планирует повтор. После исчерпания попыток журнал показывает техническую ошибку. Если исходящая SMTP-отправка оборвалась после начала передачи и её результат неизвестен, журнал показывает «Доставка неизвестна». Режим с Resend доступен через `compose.resend.yaml` после подтверждения домена и установки ключа скриптом `enable-resend.sh` на Linux.


Для теста с локальным бэкендом на Mac запусти Навигатор по [инструкции](../materials/DEPLOY.md) и задай в панели бота `http://host.docker.internal:8000/api/mail/analyze`. Контейнер Docker Desktop использует этот адрес для подключения к Mac. Ссылки на источники в письме будут открываться на компьютере, где запущен Навигатор.
