# Локальная подготовка базы и поиск

## Подготовка и запуск

Нужны Docker с Compose и интернет для первой сборки/скачивания весов. CPU достаточно; стартовый ориентир — 4 GiB памяти контейнеру ingest и 5 GiB свободного диска под образы, зависимости, модель и индекс. Это ориентир, не измеренный максимум. Python 3.12, зависимости зафиксированы в `uv.lock`; Linux использует CPU PyTorch. Веса E5 занимают около 0,5 GB. Qwen этому этапу не требуется.

Получите документы разрешённым способом в `data/raw/`. Исходный комплект — 20 файлов (9 PDF, 8 DOCX, 3 XLSX). Отдельно нужен локальный `data/manifest.json` с массивом `files` (поля `name`, `document_id`, `sha256`) и `expected_count`. Документы и реестр не входят в Git. Для нового собственного набора реестр необязателен.

Скопируйте `.env.example` в `.env`, установите свой локальный `POSTGRES_PASSWORD` из букв/цифр. Для CLI на хосте укажите тот же пароль в `DATABASE_URL`. Compose читает `.env`, CLI сам его не загружает.

```sh
docker compose build ingest
docker compose up -d postgres
docker compose run --rm ingest download-model
docker compose run --rm -v ./data/manifest.json:/app/manifest.json:ro ingest ingest --manifest /app/manifest.json --allow-warnings --timeout 900
docker compose run --rm ingest search "Как оформить командировку?" --limit 5
```

Собственный набор без реестра:

```sh
docker compose run --rm ingest ingest --allow-warnings --timeout 900
```

Остановка с сохранением БД:

```sh
docker compose stop
```

БД доступна на `127.0.0.1:5433`, внутри Compose — `postgres:5432`. Только БД использует `DATABASE_URL`; внешних LLM/embedding/OCR API нет. Оригиналы монтируются read-only. Веса — `models/`, блоки/отчёты — `data/processed/`, БД — volume `pgdata`. Эти данные не включаются в Git или Docker build context. После подготовки весов и образов обработка не требует сети.

## Контракты и поток данных

`оригинал → проверка → изолированное извлечение/OCR → SourceBlock → Chunk → E5 → поколение корпуса → поиск`

- `extractors.py`: PDF постранично с OCR; DOCX в порядке блоков/таблиц, с заголовками, нумерацией и колонтитулами; XLSX с листами, адресами, объединениями, формулами и кэшем отдельно.
- `pipeline.py`: отдельный процесс на файл, отчёты, стабильные ID и сверка реестра. Новые файлы добавляются в каталог и импортируются той же командой.
- `chunking.py`: точные срезы исходных блоков с символьными смещениями; предпочтение границ предложений/абзацев и проверка токенизации.
- `embedding.py`: `intfloat/multilingual-e5-small`, revision `fd1525a9fd15316a2d503bf26ab031a61d056e98`, 384 измерения. `passage:` для фрагментов, `query:` для вопросов, максимум 512 токенов вместе с префиксом и спецтокенами. Скачивание — только отдельной командой; inference — `local_files_only=True`, без fallback в облако. Локальные хеши фиксируют скачанные файлы, не являются независимой подписью издателя.
- `storage.py` и `schema.sql`: immutable версии, членство фрагментов в поколении, транзакционное переключение активного корпуса. Поиск exact cosine + русский FTS, объединение рангов через RRF.

`search` возвращает кандидатов: название документа, точный текст, локатор, chunk/version/corpus ID, цитаты со строками, соседний контекст и предупреждения извлечения. Это **не нормативный ответ и не оценка достаточности сведений**. RRF score — поисковый ранг, не вероятность правильного ответа. Длинные вопросы разбиваются на части. Предел — 20000 символов и 32 уникальные поисковые части; превышение явно отклоняется. Исходный поиск без разбиения доступен через `--baseline`.

Каждый импорт — полный снимок каталога: удалённый файл исчезает из активного поиска, исторические версии сохраняются. Повтор одинакового результата извлечения/модели не создаёт дублей. Изменение файла или результата OCR создаёт новую версию. Команда `index --report` переиспользует извлечённые блоки после проверки хешей оригиналов и артефактов; embeddings пока пересчитываются. Без реестра ID зависит от имени; для устойчивости при переименовании нужен явный `document_id` в реестре.

## Статусы и ограничения

`data/processed/report.json` содержит статус каждого файла (`complete`, `partial`, `error`), предупреждения, отсутствующие файлы и `published`. Блоки с текстом/локаторами/метаданными — `documents/<version_id>.json`. Эти артефакты конфиденциальны наравне с оригиналами.

Ошибка файла, пустой корпус, отсутствующий ожидаемый файл или несовпадение SHA-256 запрещают публикацию; прежний индекс остаётся активным. Предупреждения требуют `--allow-warnings`: доступные блоки можно индексировать, сохраняя ограничения. Такой корпус не объявляется полностью проверенным. Ошибка модели/БД сохраняется как `index_error`, не как отсутствие информации.

Коды завершения: `extract` — 0 при техническом успехе, 2 при частичном извлечении, 1 при ошибке; `ingest` — 0 после публикации (также с явно разрешёнными предупреждениями), 2 если публикация требует разрешения предупреждений, 1 при ошибке. Фактический статус качества остаётся в отчёте.

Ограничения первого этапа:

- PDF-таблицы и порядок чтения требуют визуальной сверки. OSD определяет поворот перед OCR, неопределённая ориентация отмечается. Изображения внутри Form XObject учитываются; декоративный пиксель не вызывает замену читаемого текста OCR. Ошибка OCR или потеря страницы показывается предупреждением.
- Сложные переопределения DOCX-нумерации, исправления/рисунки помечаются. Страницы Word не выдумываются.
- Первая непустая строка XLSX используется как контекст с явной пометкой, что это не проверенный заголовок. Формулы не исполняются; кэш, в том числе отсутствующий, не объявляется пересчитанным.
- Лимиты: 100 MiB на файл, 256 MiB распакованного Office ZIP, 10000 ZIP entries, 1000 PDF pages, 500000 ячеек на лист. Макросы/DTD/entities запрещены. Таймаут на файл по умолчанию 300 секунд (до 3600), OCR имеет отдельные таймауты. При общем таймауте завершается группа процессов извлечения/OCR.
- Применимость документов, приоритет редакций, связь приложений с основным документом, содержательная проверка цитат и генерация ответов пока не реализованы. Оценка качества поиска на эталонных вопросах ещё требуется.

## Разработка и проверки

На хосте нужны `uv` и Python 3.12; для OCR — Poppler (`pdftoppm`), Tesseract и языки `rus`/`eng`. В контейнере инструменты установлены.

```sh
uv sync --frozen
uv run navigator --help
uv run navigator extract --manifest data/manifest.json --no-ocr
uv run pytest -q --tb=short
```

`--no-ocr` — диагностика: сканы останутся неполными. Для `db-init`, `ingest`, `search` на хосте экспортируйте `DATABASE_URL`. Для интеграционного pytest экспортируйте `TEST_DATABASE_URL` на тестовую БД с pgvector; тест создаёт/удаляет только свою случайную схему. Без переменной он явно пропускается. Не выводите секретные переменные в логи.

## Два синтетических примера

```sh
uv run python examples/make_documents.py
uv run navigator extract --input data/processed/demo-input --output data/processed/demo-output
```

1. Вопрос «Как получить учебный набор?» — `synthetic-procedure.docx` содержит два тестовых действия: подать тестовую заявку учебному координатору и получить подтверждение. Ожидаются текст и локаторы этих блоков; это вымышленные учебные положения.
2. Проверка суммы в `synthetic-budget.xlsx` — сохраняются ячейка `C2`, формула `=A2*B2`, отсутствующий кэш и `cache_verified=false`. Значение не подменяется результатом расчёта. Из-за непроверенных формул `extract` завершится кодом 2; это ожидаемо.

Для поискового демо индексируйте этот набор в отдельную БД: публикация переключает активный корпус. Синтетические тесты не доказывают качество на исходных регламентах.

## Наблюдаемая проверка 12.11.2026

На локальном комплекте импорт с Linux OCR в Docker прочитал 20/20 файлов без файловых ошибок, распознал 49 страниц и опубликовал 2924 фрагмента. Статус `partial`: 11 файлов имеют предупреждения извлечения, в том числе о PDF-таблицах/OCR и непроверенном кэше формул. Это техническая проверка импорта, не подтверждение полноты нормативного анализа.

Проверены точные срезы всех опубликованных фрагментов, повторная публикация той же генерации без роста числа фрагментов/поколений и поиск по реальному корпусу. Для одного пробного запроса поиск вернул фрагменты ожидаемого тематического документа; Recall@k на размеченном наборе ещё не измерен. Полный pytest с локальной PostgreSQL: 32 passed. Проверка выполнена на macOS arm64 с Linux arm64 контейнерами; Linux amd64 и чистый чужой компьютер пока не проверены.

Финальный Docker-образ собран: из него проверены поиск по опубликованному корпусу (5 результатов с предупреждениями источников) и извлечение двух синтетических DOCX/XLSX. Для синтетического XLSX получен ожидаемый `partial` и код 2 из-за непроверенного кэша формулы.
