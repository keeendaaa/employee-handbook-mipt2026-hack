# employee-handbook-mipt2026-hack

Кейс № 4: «Навигатор сотрудника по внутренним регламентам».

Демонстрация: **[smena-mipt.ru](https://smena-mipt.ru)**. [Сценарии для эксперта](materials/DEMO.md).

[Схемы бэкенда для защиты](output/README.md): общий PDF и четыре PNG в 4K — архитектура, ingest, поиск и карта модулей.

Система должна находить ответ на вопрос сотрудника в предоставленных документах, формировать порядок действий и подтверждать ключевые выводы источниками.

## Фронтенд Смена

В `main` объединён React19 интерфейс «Смена» по Figma: задача → декомпозиция → этапы с цитатами → отметки и продолжение; админские импорт, карта, проверка вопросов, запросы материалов и почтовая панель. [Запуск, API-контракт и проверки](frontend/README.md). Dockerfile собирает UI вместе с API; новый UI открывается на `/`, прежний — на `/legacy`. Сохранены актуальные исправления почтового бота из `main`. Обновление 1.3.1 со статичным знаком МФТИ, нейтральным preview цитаты и общим анимационным preset развёрнуто на `https://smena-mipt.ru`; протокол — в [VALIDATION.md](materials/VALIDATION.md).

## Текущий статус

Сохранены условия кейса и правила разработки. Локально загружены все 20 исходных файлов в `data/raw/`, реестр загрузки — `data/manifest.json`. Эти данные исключены из Git до подтверждения разрешения на публикацию и не входят в клонируемый репозиторий.

Выполнен первичный скрининг данных; разрешение на перепубликацию не подтверждено.

Реализован первый этап бэкенда: локальное чтение PDF/DOCX/XLSX, OCR, E5 embeddings, PostgreSQL + pgvector, атомарные поколения индекса и поиск фрагментов (dense + русский FTS + RRF). Инструкция запуска, проверки и ограничения — в [INGEST.md](materials/INGEST.md). Добавлены HTTP API, страница с открытием цитат по строкам и генерация через внешний Qwen 27B. Автоматическое разрешение редакций не реализовано. Новый frontend сохраняет пользовательские отметки процедуры в браузере; они не подтверждают операции во внешних системах. Запуск и ограничения — в [DEPLOY.md](materials/DEPLOY.md).

Добавлена общая карта знаний (`/map`): темы из фрагментов разных файлов, смысловые связи, открытие источников и проверенные вопросы с отмеченными пробелами. Неподтверждённый ответ, техническая ошибка и проверка на прежней версии базы различаются. [Как устроена карта](materials/DEPLOY.md#общая-карта-знаний).

Добавлены загрузка PDF/DOCX/XLSX и импорт публичных ссылок через интерфейс в общую базу. Фоновый обработчик сохраняет оригиналы, показывает предупреждения и не создаёт дубликаты идентичных файлов. [Форматы, лимиты и запуск обработчика](materials/DEPLOY.md#загрузка-документов-из-интерфейса).

Поиск поддерживает длинные и составные вопросы, соседний контекст, проверяемые цитаты со строками и повторную индексацию без OCR. Проверочный набор, метрики и контракт открытия источника — в [RETRIEVAL.md](materials/RETRIEVAL.md).


Почтовый бот использует `POST /api/mail/analyze` и отправляет ответ с шагами и источниками в той же цепочке. Он запускается отдельным Docker Compose. [Настройка почтового бота](mailbot/README.md).

## Структура репозитория

Организация следует привычному разделению School 21:

```text
src/navigator/       код бэкенда, API и встроенная страница
  ingest/            извлечение, OCR, embeddings и хранение
  static/            интерфейс демонстрации
mailbot/             обработчик почты, панель и отдельный Docker Compose
tests/               автоматические проверки
materials/           задание, критерии, архитектура и инструкции
code-samples/        генератор синтетических учебных документов
misc/scripts/        служебные проверки развёрнутого сервиса
data/                оригиналы и результаты обработки (локально)
models/              скачанные веса E5 (локально)
secrets/             ключ внешней модели (локально)
```

`pyproject.toml`, `uv.lock`, `Dockerfile`, `compose.yaml` и пример окружения находятся в корне. Команды из инструкций выполняются из корня репозитория. Назначение и статус исходных данных описаны в [data/README.md](data/README.md).
