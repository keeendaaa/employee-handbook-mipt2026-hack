# Задача 4. Навигатор сотрудника по внутренним регламентам

Источник: https://docs.google.com/document/d/1kxO1dHuL6MPziqzHNoKuJyRpY3WtRt0i/edit#heading=h.zdewywg1b14d

Документ сохраняет основные условия задания. Полный перечень входных материалов находится в [DOCUMENTS.md](DOCUMENTS.md), полная разбалловка и внутренний план проверки — в [CRITERIA.md](CRITERIA.md), правила работы агентов — в [AGENTS.md](../AGENTS.md).

## 1. Полное описание задачи

Необходимо разработать систему, которая по вопросу сотрудника находит подходящий внутренний регламент или приказ и формирует понятный порядок действий на основании найденных документов.

Решение должно указывать использованные документы, давать краткую последовательность шагов и сообщать об отсутствии подходящей информации, если необходимого ответа нет в предоставленной базе. Ответ должен быть основан на документах, а не на общих знаниях модели.

## 2. Входные данные

- Вопрос сотрудника на естественном языке.
- Предоставленная база внутренних регламентов, приказов, форм и приложений: **20 файлов — 9 PDF, 8 DOCX, 3 XLSX**.
- Названия и описания всех файлов перенесены в [DOCUMENTS.md](DOCUMENTS.md).

Сами регламенты не входят в текст задания. Перечень материалов и их краткие описания нельзя использовать вместо содержимого документов для генерации нормативных ответов.

## 3. Ожидаемый результат работы решения

На выходе должен формироваться ответ, который можно проверить по предоставленной базе документов:

1. Краткий ответ на вопрос пользователя.
2. Пошаговый порядок действий, если документ описывает процедуру.
3. Название документа или документов, на основании которых сформирован ответ.
4. Ссылка на конкретный раздел, пункт или фрагмент документа, если структура документа это позволяет.
5. Отдельное сообщение, если в предоставленной базе нет информации, достаточной для ответа.
6. При наличии нескольких релевантных документов — объединенный ответ без противоречий и с указанием каждого использованного источника.

В критериях дополнительно прямо указано: каждый ключевой вывод должен содержать название документа и ссылку на конкретный пункт или фрагмент; противоречия и неоднозначности между документами должны показываться пользователю.

## 4. Ограничение на внешние API

> Через любые внешние API можно передавать только открытые (/не конфиденциальные) данные.

Это условие задания. Оно не означает, что все предоставленные материалы автоматически являются открытыми, и не запрещает внешние API для действительно открытых данных.

Внутренние правила безопасной обработки и уточнения статуса материалов описаны в [AGENTS.md](../AGENTS.md).

## 6. Артефакты и свойства, прямо указанные в критериях

- Dockerfile; для многокомпонентного решения — Docker Compose.
- Запуск в чистом окружении по инструкции без ручного изменения исходного кода.
- README с требованиями к окружению, командами запуска и остановки, зависимостями, настройками, переменными окружения и перечнем внешних сервисов.
- Описание архитектуры, ключевых компонентов и потока данных от входа до результата.
- Не менее двух типовых use cases с примером входа и ожидаемого результата.
- Сквозной основной пользовательский сценарий и рабочая демонстрация с возможностью тестирования.
- Для дополнительных отраслевых баллов — полезные реализованные дополнительные возможности с показанной ценностью, реалистичный план развития или внедрения и понятное выступление.

## 7. Что в предоставленном задании не определено

Следующие пункты нужно уточнять, а не придумывать от имени организаторов:

- Сроки, канал и формат сдачи, длительность защиты.
- Способ получения исходных 20 файлов и статус конфиденциальности каждого материала.
- Конфигурация окружения проверки, доступность интернета, CPU/GPU и памяти.
- Конкретные модели, стек, поисковая архитектура и база данных: они не предписаны.
- Состав скрытых проверок, пороги качества и метод начисления частичных баллов.
- Ожидаемая глубина работы с XLSX: извлечение содержимого или также выполнение расчетов.
- Требуется ли опубликованный стенд или достаточно доступной локальной демонстрации.

Этот список — зафиксированные пробелы исходного задания, а не дополнительные требования к сдаче.
