Результаты ответа: answered → ответ; partial → подтверждённая часть отдельно от missing_information; not_found → отсутствие подтверждения; needs_clarification → редактирование исходной задачи; conflict → разбор расхождения. summary и steps состоят из утверждений с citation_ids; не показывать утверждение как подтверждённое без соответствующего источника. Технический error не превращается в not_found.

Ограничения: вопрос обычного поиска1–20000 символов; общий проверяемый вопрос1–500; limit1–20. Смена корпуса делает сохранённый результат stale. Успех импорта сам по себе не устанавливает актуальность редакции документа и не подтверждает все прежние ответы.

## Состояния импорта

| Данные API | ProcessStatus |
|---|---|
| queued | Queued |
| downloading | Downloading |
| extracting | Extracting |
| indexing | Indexing |
| ready, duplicate=false | Ready |
| partial | Warning |
| ready, duplicate=true | Duplicate |
| failed | Failed |

Duplicate — отдельное представление флага, а не новый status API. partial — добавление с предупреждениями. worker_available=false у незавершённой задачи означает паузу обработчика: задачу нельзя объявлять потерянной или успешно завершённой. Новые импорты могут быть отклонены503 при недоступном worker. Ошибка ссылки, превышение25МБ и неподдерживаемый формат требуют исправления ввода. Нельзя выдавать их за завершение загрузки.

replace_existing задаётся пользователем явно. Совпадение содержимого не создаёт копию; изменённый одноимённый файл не заменяет прежний без согласия. Лимиты демонстрации:10 попыток/час на IP,40 принятых задач за24часа на базу, до5 незавершённых задач. Сообщение об исчерпании лимита сохраняет ввод и возможность повторить позже.

## Почтовая панель

[Исходная панель](https://github.com/keeendaaa/employee-handbook-mipt2026-hack/blob/d1c31ce938b733e4ffae0fa3ea9ec6ad9438b8d1/mailbot/panel.html) перенесена в визуальную систему «Смены». Настоящие поля ответа GET /api/status:

- mailbox — адрес ящика;
- worker: state,updated,detail;
- settings: enabled,reply_without_issue,senders,api_url;
- events: sender,subject,status,detail,updated; последние50 событий.

worker.state: starting,online,paused,error. Unavailable — ошибка запроса панели; это не значение worker.state. Test — режим, вычисляемый по пустому api_url. Пауза меняет enabled и сохраняет остальные поля настроек.

| event.status | Подпись |
|---|---|
| pending | В очереди |
| sending | Отправляется |
| sent | Ответ отправлен |
| skipped | Пропущено |
| retry | Повтор запланирован |
| failed | Ошибка |
| uncertain | Доставка неизвестна |

uncertain нельзя автоматически переводить в failed или sent, повторять письмо вручную без проверки тоже нельзя: после обрыва SMTP отправка могла состояться. В панели нет endpoint ручного повтора, полного письма, поиска журнала или фильтра на сервере. Макет не добавляет такие кнопки. Адреса и темы в макете — example.org, данные реальных писем не читались.

POST /api/settings получает весь набор: enabled:boolean,reply_without_issue:boolean,senders:string[],api_url:string. До100 корректных адресов, длина каждого до254; сервер приводит к casefold и удаляет дубликаты. Пустой senders разрешает все адреса. API URL до2048: HTTPS, без credentials/query/fragment, путь /api/mail/analyze; для совместимости сервер принимает /api/ask, но клиент бота использует mail/analyze. Пустое значение включает тестовый ответ. Не выводить пароли почты или ключи API в настройках браузера.

Обновлять состояние раз в10с; при dirty/saving форме не перезаписывать поля ответом фонового запроса. Сохранение блокирует поля и повторный submit, затем показывает успех или ошибку. При неуспехе оставлять введённые значения.

Сам бот читает IMAP STARTTLS143 и отправляет ответ в исходную цепочку SMTP STARTTLS587. Вызывает POST /api/mail/analyze `{subject,body}`. Передаёт тему и извлечённый текст, без адреса отправителя, HTML и вложений. Каждое письмо анализируется отдельно. Ответ no_action пропускается или подтверждается в зависимости от reply_without_issue. Сеть и временные ошибки планируют повтор; после исчерпания попыток появляется failed.

### Подключение общей админки

Текущая панель привязана к127.0.0.1:8787. Host должен совпасть, а POST дополнительно требует Origin http://127.0.0.1:8787. Браузер на публичном домене не может просто вызывать эти маршруты. Для интеграции нужен серверный шлюз с авторизацией и отдельным namespace; нельзя решать это отключением проверок Host/Origin или публичным открытием панели. Параметры IMAP/SMTP и пароль остаются серверными. Шлюз добавлен в frontend-ветке версии1.2; его контракт описан ниже.

Ожидаемый срок для зала и граница пункта2.4 взяты из [materials/DEMO.md](https://github.com/keeendaaa/employee-handbook-mipt2026-hack/blob/e7cb2f82df099a3c8d793a14d5a3a64e8a38b52e/materials/DEMO.md). Перечень файлов — [materials/DOCUMENTS.md](https://github.com/keeendaaa/employee-handbook-mipt2026-hack/blob/e7cb2f82df099a3c8d793a14d5a3a64e8a38b52e/materials/DOCUMENTS.md). Оригиналы20 документов отсутствуют в Git, поэтому полноценная проверка их текста в этой итерации не выполнялась.

Текст на03 — пересказ ожидаемого основания, не точная цитата. В рабочем продукте нужно отобразить quote из API со строками и локатором. Часть примеров использует составной вопрос «бронирование + тариф», чтобы источник в прототипе был согласован с открываемым D01. Реальный конфликт регламентов не утверждается:21 показывает контракт состояния. Граф иллюстрирует источник/фрагмент, смысловую близость и неподтверждённый вопрос. Смысловая близость не доказывает, что один регламент требует другой; формальные нормативные зависимости добавляются только после проверки явных ссылок в документах.


## Контракт реализации 1.2

01→23→02 создаёт задачу из `POST /api/query/stream`. `answer.steps[].text` — подтверждённое действие, `citation_ids` — только источники данного действия. При пустом steps не сочинять процедуру и не разрешать фиктивное завершение. Отдельный запрос подробностей этапа повторно вызывает этот же RAG endpoint с контекстом исходной задачи и выбранным шагом. Исходный план и отметки при этом не заменяются.

GET /api/sources/{source_id} возвращает block_text и точные start/end; выделять этот диапазон только при совпадении с quote. При404 показывать ошибку источника, сохраняя задачу. Технические ошибки потока не становятся not_found или дефектом регламента.

Ветка frontend включает существующую codex/mailbot и её /api/mail/analyze. Добавлен шлюз /api/admin/mail/status и /api/admin/mail/settings. Он требует ADMIN_API_TOKEN, обращается к серверному MAILBOT_PANEL_URL и сохраняет внутренние Host/Origin проверки панели. IMAP/SMTP пароли в браузер не передаются. Общая полноценная ролевая модель не добавлялась; карту и импорт регулирует существующая модель публичной демонстрации.

Запрос материалов: POST /api/material-requests {question,message,step,source_ids,public_data:true}; GET и PATCH /api/material-requests/{id} доступны администратору. Статусы new/review/closed — работа над запросом, а не автоматическое доказательство пробела регламента. Хранилище MATERIAL_REQUEST_DB по умолчанию data/workspace/requests.sqlite. Compose сохраняет каталог.

Публичный HR PDF из Figma не зашит во frontend и не подменяет ответ API. До импорта в реальный корпус этот сценарий может не подтверждаться; пользователь получает реальные missing_information. Актуальный frontend-контракт и команды находятся в frontend/README.md и frontend/design-system/ репозитория.
