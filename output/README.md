# Схемы бэкенда для защиты

Четыре схемы формата 16:9 описывают реализованный код на 13 ноября 2026 года. PDF содержит векторные фигуры и встроенные шрифты; PNG имеют размер 3840 × 2160. В PDF есть оглавление, ссылка на демо внизу каждой страницы открывается по клику.

- [Общий PDF: четыре страницы](pdf/smena-backend.pdf)
- [Все PNG в 4K одним архивом](diagrams/smena-backend-png-4k.zip)

| Схема | Для чего показать | Ключевая мысль |
|---|---|---|
| [01. Общий вид](diagrams/01-system.png) | Начало рассказа | Браузер обращается к API; локальные поиск и обработка отделены от внешней генерации. |
| [02. Загрузка документов](diagrams/02-ingestion.png) | Объяснение ingest | Файл проходит очередь, извлечение и E5; новый снимок индекса публикуется атомарно. |
| [03. От вопроса к ответу](diagrams/03-question-to-answer.png) | Основной сценарий | Смысловой поиск и русский FTS объединяются через RRF; ответ связан с открываемыми цитатами. |
| [04. Карта модулей](diagrams/04-code-map.png) | Технические вопросы жюри | Показаны реальные файлы в `src/navigator/` и их обязанности. |

Для короткой защиты достаточно схем 01 и 03. Схема 02 раскрывает обработку документов, 04 помогает перейти к просмотру кода. Каждая страница читается самостоятельно.

Границы проверяемости показаны явно: сервер проверяет структуру ответа, существование ссылок и точные координаты текста; смысловую связь вывода с цитатой оценивает модель. Предупреждения OCR сохраняются. Расшифровки корпусов используются как подсказки для поиска. Диаграммы не заявляют автоматического разрешения редакций.

## Выбор визуального подхода

Изучены три подхода:

- [C4](https://c4model.com/diagrams) — последовательное раскрытие архитектуры от общего устройства к компонентам. На этой логике построена серия; строгая нотация C4 не заявляется.
- [D2](https://d2lang.com/tour/exports/) — схемы из текстового описания с экспортом в SVG, PNG и PDF. Подходит для дальнейшей автоматизации архитектурной документации.
- [Excalidraw Libraries](https://libraries.excalidraw.com/) — библиотечные элементы, в том числе для архитектурных набросков.

Для текущих иллюстраций выбран программный рендеринг с точным расположением подписей и стрелок. Из предоставленного пользователем скилла `saas-animation` использованы принципы визуального оформления: короткие строки, один акцентный цвет, ясный центр композиции и последовательная история. Схемы статические.

## Повторная сборка

Исходник: [render_backend_diagrams.py](../misc/scripts/render_backend_diagrams.py). Он не меняет код приложения, базу и зависимости проекта. Инструменты рендеринга подключаются к одноразовому окружению `uv`:

```sh
uv run --with reportlab==5.1.0 --with pymupdf==2.1 python misc/scripts/render_backend_diagrams.py
```

По умолчанию используются системные шрифты macOS из `/System/Library/Fonts/Supplemental`. На другой машине передайте `--font-dir` с `Arial.ttf`, `Arial Bold.ttf`, `Andale Mono.ttf`; шрифты в репозиторий не включены. `--output` позволяет выбрать другой каталог результатов. Генератор проверяет ширину подписей, высоту карточек, число страниц и размер PNG. После сборки страницы проверены визуально по фактическому рендеру PDF.
